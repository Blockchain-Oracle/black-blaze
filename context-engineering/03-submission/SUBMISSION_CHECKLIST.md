# Submission Checklist

## Mandatory project deliverables

- [ ] Working generative-media app using **Backblaze B2** and **Genblaze**.
- [ ] Stable app URL judges can easily access, test, and evaluate.
- [ ] Test account and unambiguous login instructions if authentication is required.
- [ ] App remains free and available through **Aug 11, 2026, 5:00 PM EDT / 10:00 PM WAT**.
- [ ] Public or private GitHub repository.
- [ ] Repository contains all necessary source, required assets, and setup instructions.
- [ ] Private repository grants the reviewer account access. The overview names `https://github.com/b2genblaze`; recheck immediately before submission.
- [ ] Text description explains features and functionality.
- [ ] Text description explicitly explains **how B2 is used**.
- [ ] Text description explicitly explains **how Genblaze is used**.
- [ ] Exact list of AI providers and model slugs used.
- [ ] Public YouTube, Vimeo, or Youku demonstration video.
- [ ] Video duration is **less than 3:00**; judges need not watch beyond 3:00.
- [ ] Video shows the project functioning on the intended device/platform.
- [ ] English materials or English translations.

## Strong evidence package

Not separately mandated, but strongly recommended:

- [ ] Architecture diagram mapping each generation/storage step.
- [ ] Screenshot or in-app view of B2 object organization.
- [ ] Real manifest with provider, model, prompt policy, hash, and asset URLs redacted as needed.
- [ ] `genblaze verify --fetch` or equivalent integrity evidence.
- [ ] Failure/fallback demonstration or automated test evidence.
- [ ] Live health/readiness endpoint.
- [ ] Seeded demo workspace so judges see value immediately.
- [ ] Cost/latency indicators and retry behavior.
- [ ] CI status and one-command local setup.

## Optional feedback-prize entry

- [ ] Use Genblaze in a real path first.
- [ ] Search existing issues to avoid duplicates.
- [ ] Submit a reproducible bug report, viable feature request, or complete general feedback.
- [ ] Include package versions, minimal reproduction, observed/expected result, impact, and a practical proposal.
- [ ] Link the issue in the Devpost submission.

## Final-hour controls

- [ ] Submit at least 6 hours before deadline; target **Aug 3, 4:00 PM WAT**.
- [ ] Test app in an incognito browser from a separate network/account.
- [ ] Test the video while logged out.
- [ ] Test repository access and README from a clean clone.
- [ ] Scan repository history for secrets.
- [ ] Freeze provider/model versions used in demo.
- [ ] Export final Devpost text and links to this repo.
- [ ] Capture confirmation screenshots and submission timestamp.
- [ ] Do not modify the competition submission after cutoff unless explicitly allowed.
